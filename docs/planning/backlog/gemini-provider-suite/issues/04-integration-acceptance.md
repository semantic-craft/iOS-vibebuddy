**What to build:** 收敛并修复三项能力一起使用时的集成问题，使同一套 Gemini 配置从任务完成摘要、听取结果到语音操作真正贯通，并保留用户已有配置。

## Acceptance criteria

- [ ] Mac/iPhone 走完用户确认的三条真实流程：完成结果 → 摘要；指定结果 → 朗读；实时通话 → 查询/受控操作 → 回执。
- [ ] Gemini 朗读期间启动 Gemini 通话，播报按现有规则暂停；挂断后手动队列不擅自恢复；旧音频/工具结果不串入新轮次。
- [ ] 三用途独立切换、朗读跟随与固定、两端重启后设置保持、未配置不自动启用等联合场景通过；原千问等配置不被改变。
- [ ] 手机继续使用来源 Mac 的证据与内容风格；断线/过期结果不生成错误摘要，不把听到结果视为已读或完成验收。
- [ ] 修复本次联合流程暴露的缺陷，并只重跑受影响检查；复用 01–03 已有有效证据，不无理由重跑全部测试或模型比较。
- [ ] 汇总实际代码版本、默认模型及 SDK 版本、构建、真实调用、设备实听、错误恢复、已测/未测供应商时限；不能将设备/凭据缺口标为通过。
- [x] 对最终差异做规范与 PRD 两轴评审，处理有效发现；领域文档描述最终行为且保留历史移除记录。
- [ ] 所有 PRD 验收门槛满足才宣告整套交付；安装、发布、提交和用户最终体验确认与代码验证分别记载。

**执行约束：** 使用 verify-vibebuddy 的隔离实例；不默认启动第二个生产菜单栏实例或替换共享已安装 App。缺少真实调用/设备验收条件时完成可运行工作并明确剩余项。
