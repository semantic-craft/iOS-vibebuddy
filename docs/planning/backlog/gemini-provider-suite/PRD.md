# Gemini 摘要、朗读与实时通话

Status: ready-for-agent
日期：2026-10-04
阶段：规格完成，待拆实施工单；产品尚未实现。
代码基线：`5af77f161cd28386beeda8b6c98853811013f43e`

## Problem Statement

用户希望像现有千问一样，使用 Gemini 完成任务摘要、结果朗读和实时语音交互，并能分别选择三种用途。当前产品已移除 Gemini，用户无法配置这套组合；旧启动迁移还会删除 Gemini 的设置和凭据，单纯恢复供应商选项会造成新配置丢失。

用户还要求参考 Google 官方文档、开源 SDK 和示例。官方 Swift SDK 的 Firebase 项目/代理要求与当前自带 Key 的体验不同，旧 Gemini 实现及部分官方示例也已落后于当前协议，不能照搬。

## Solution

在 Mac 与 iPhone 的现有供应商设置中重新提供 Gemini，覆盖摘要、朗读、实时通话三个用途。用户在需要直连 Google 的设备配置自己的 Key，每个用途保存独立模型和适用的声音偏好；朗读继续支持跟随摘要供应商或单独固定。保留现有自动播报开关、任务操作权限和阅读状态语义。

产品使用 Swift 原生 HTTP/WebSocket 直连 Google，复用现有摘要服务、朗读播放器与语音协调器。Google 官方 GenAI SDK 用作协议参考与独立验收对照，不成为产品额外运行时。配对手机继续从来源 Mac 获取原始任务证据和内容呈现；不借此次接入迁移摘要服务或同步 Key。

| 用途 | 实施候选 | 默认值确定方式 |
| --- | --- | --- |
| 完成摘要及朗读文本呈现 | `gemini-3.5-flash-lite`、`gemini-3.8-flash` | 同一批真实任务结果比较准确性、耗时和用量，再确定默认；用户可改模型 |
| 结果朗读 | `gemini-3.8-flash-lite-tts` | 先验证短文本中文/英文播报；`gemini-3.8-flash-tts` 作为音色表现比较项 |
| 实时通话 | `gemini-3.8-live` | 验证音频、转写、工具执行与取消，符合现有通话体验 |

这些是前期官方资料核对所得的候选，不是已测可用性或性能承诺。文本模型不填写不存在于当前已核实目录的 `gemini-3.8-flash-lite`；带 `-tts` 的型号不用于摘要。

## User Stories

1. 作为 Mac 用户，我希望在账户设置中填写 Gemini Key，以便使用自己的 Google 账户。
2. 作为 iPhone 用户，我希望沿用手机已有的凭据配置方式，以便手机语音直接连接 Google。
3. 作为用户，我希望摘要、朗读和通话可分别选择供应商，以便按用途组合 Gemini 与现有服务。
4. 作为用户，我希望更改通话模型不改变摘要模型，以便已有通知行为保持稳定。
5. 作为用户，我希望朗读可跟随摘要供应商或固定 Gemini，以便保留自己喜欢的声音。
6. 作为用户，我希望每个用途记住模型和声音设置，以便切换供应商后仍保留偏好。
7. 作为用户，我希望未配置 Key 时仍能查看和处理任务，以便语音保持可选。
8. 作为用户，我希望连接检查明确说明检查范围，以便区分连接成功与声音实际可用。
9. 作为用户，我希望完成摘要只描述当前轮真实结果，以便不会把旧结果当成新进展。
10. 作为用户，我希望摘要遵循已选语言和内容风格，以便 Gemini 的通知与现有产品一致。
11. 作为用户，我希望能比较两种摘要模型的真实效果，以便默认选择有证据支持。
12. 作为用户，我希望手动朗读和自动播报使用确定的结果文本，以便声音不会自行补充任务结论。
13. 作为用户，我希望能试听、选择预置声音和播报风格，以便找到听得清的声音。
14. 作为用户，我希望停止、跳过、重播和队列继续正常工作，以便控制何时听取结果。
15. 作为用户，我希望听到结果不会自动标为已读，以便保留现有阅读流程。
16. 作为用户，我希望可以用语音查询当前任务状态，以便离开键盘时仍能了解进度。
17. 作为用户，我希望现有语音任务操作只针对明确指定且当前可操作的任务，以便不会误操作同名或过期任务。
18. 作为用户，我希望模型收到应用回执后再确认操作结果，以便不会把请求发送说成任务完成。
19. 作为用户，我希望打断或挂断后旧音频和取消的调用不会继续执行，以便通话停止可靠。
20. 作为用户，我希望通话期间暂停朗读，以便两个声音不会同时播放。
21. 作为用户，我希望断网、Key 错误、配额与供应商时限有明确反馈，以便知道如何恢复。
22. 作为用户，我希望达到通话时限后可以重拨，以便用新通话继续操作。
23. 作为重新配置 Gemini 的用户，我希望重启后新 Key 和设置仍保留，以便旧移除逻辑不会再次清空配置。
24. 作为已有用户，我希望更新不会自动切换供应商或开启麦克风、摘要和播报，以便保持当前选择。

## Implementation Decisions

- **供应商与用途**：Gemini 同时声明摘要、TTS、实时语音能力，沿用 VoiceProvider 与现有三用途设置。保留原有供应商，失败不静默切换厂商、Key、模型或计费入口。
- **职责边界**：摘要由 CompletionSummaryHTTP/内容呈现服务负责，TTS 实现 SpeechSynthesizer，Live 实现 RealtimeVoiceProvider，任务操作复用 VoiceCallCoordinator。Mac/iPhone 复用共享适配器，平台音频仍由现有平台实现负责。
- **SDK 选择**：使用官方文档和固定版本 SDK 核对请求/事件。产品不依赖 Firebase，不加入 Python/JS 后台进程。验收探针可使用官方 GenAI SDK，记录发布版本；不能将 main 源码存在某字段等同于已发布版本支持。
- **摘要协议**：使用 Interactions 独立请求，显式 `store=false`，不串联历史 interaction，不给摘要配置工具。解析最终可见文本和用量，排除思考内容；保留请求取消、禁止重定向、限时和错误分类。
- **内容契约**：保留通知 12 秒决策时限、180 字通知和 900 字朗读呈现上限。继续从准确来源/会话/完成轮次取得证据，生成后重新核对来源与配置；新轮次、失败、证据冲突或过期不能发布旧摘要。
- **TTS 协议**：使用 Interactions 音频输出，正文与 speech_metadata 风格分开，显式 `store=false`。首版读取完整 WAV，复用现有分段合成与播放器；检查 MIME、大小、空音频与取消。声音与风格只影响朗读表现，不改变正文事实。
- **Live 协议**：setup 确认后才认为连接可用；输入 PCM16 16 kHz、输出 PCM16 24 kHz，映射音频、双方转写、轮次结束、工具调用/取消和连接结束。沿用现有全双工/AEC 音频管线；轮次结束不等于连接结束。
- **工具执行**：首版明确配置 BLOCKING，保留调用 ID、任务身份与当前轮次检查；已有应用层授权/目标核验继续负责最终执行。取消后的迟到回包不得触发操作或朗读，不自动重试有副作用的调用。结束通话先完成现有回执交付约定。
- **当前模型差异**：遵循 3.8 Live 的字段约束，不恢复旧 thinking/affective/proactive 禁用配置。官方文档冲突以固定 SDK schema、当前协议及隔离探针核实，测试探针不执行真实任务副作用。
- **结束与重拨**：GoAway 先记录为结束预告，连接实际结束时再按明确信号映射 providerLimit；普通网络、认证和配额问题保持失败。重拨创建新通话，不携带旧工具执行状态；首版不透明恢复会话。
- **设置迁移**：删除持续清理 Gemini 设置/凭据的退役路径及两端启动调用。保留用户现存的非空显式选择；旧模型不可用时给出配置错误和恢复默认入口，不暗中换模型。已被删除的 Key 不尝试恢复，不重新开启已关闭的功能。
- **凭据与平台**：正式用户沿用设备 Keychain；Mac 摘要和每台设备语音各用其现有凭据路径。开发验收经项目入口显式注入所需变量并检查子进程继承；不因开发配置改变普通用户凭据方式。日志和错误不包含 Key、带 Key URL 或完整任务正文。
- **领域记录**：实施时追加 ADR-0001 的 Gemini 重新引入修订，保留 9 月移除的历史。沿用 ADR-0002 的直连模式、ADR-0004 的全双工/AEC和 ADR-0008 的工具执行边界；不把编码 agent 的 gemini 来源别名改为模型供应商。

## Testing Decisions

用户于本轮确认验收以三条完整流程为主：真实完成结果生成摘要、确定文本被朗读、语音查询并操作指定任务。优先从现有服务/协调器接口观察行为，不为私有辅助函数或供应商枚举逐项堆测试；新增的网络适配器内部可注入传输以重放关键响应，无需搭建通用测试框架。

| 检查边界 | 需证明的行为 | 现有先例 |
| --- | --- | --- |
| 配置与启动 | 三用途独立、朗读跟随/固定、新 Gemini Key 重启不被删、开关不自动打开 | VoicePurposeSettingsTests 与可注入的 Keychain Operations |
| 摘要/内容呈现服务 | 请求无状态、只返回最终正文；超时、取消或轮次变化不发布旧结果 | CompletionSummaryTests、CompletionSummaryPreferencesTests、ContentPresentationTests |
| 合成器到播放器 | 正文/风格分离、WAV 可播放、取消后不继续入队、失败可见 | SpeechSynthesisDecodingTests、MiniMaxSpeechTests、ChunkedSpeechSynthesizerTests |
| Live 到通话协调器 | 连接就绪、连续两轮、打断/取消、工具 ID 与回执、正确区分结束和失败 | VoiceCallCoordinatorTests、ProviderLimitSignalTests |

### 真实验收

1. **摘要**：使用一组经授权的真实 Claude/Codex 完成结果，覆盖中文、英文/代码标识符、失败/阻塞与需用户动作。同一输入和提示比较两种候选模型，记录实际模型 ID、完整请求耗时、用量、超时与事实遗漏/添加。不得把工具执行成功说成用户验收；不得凭空添加下一步。测试样本上的稳定及时和事实准确优先，成本仅在有实际用量/价格依据时比较。
2. **默认模型决策**：两种模型至少各完成同一组样本；先淘汰存在严重事实失真或经常超过通知时限的候选，再比较延迟与成本。有明显质量差异选质量更稳的；质量相当选更快、更经济的。记录选择及样本局限，不能只凭型号新旧决定。若均不满足契约，记录未通过并修正，不把功能标为完成。
3. **朗读**：Mac 和 iPhone 各完成试听和真实结果朗读，听清中文、英文标识符与数字，确认正文未增删结论；检查声音/风格、停止/跳过和通话时暂停。生成出音频与人实际听到分别记录。
4. **通话**：两端各完成短通话和连续两轮问答；读取真实任务状态；在明确授权的可控任务上验证现有操作及回执、目标核验、取消和挂断。测试通话到顶信号可用协议重放，真实供应商时限另记已测/未测，不把重放说成长通话实测。
5. **恢复与回归**：检查错误 Key、配额/限流响应、网络中断及手动重拨；现有千问等供应商设置不被修改。设置连接检查保持无麦克风、无任务上下文和工具。
6. **范围检查**：运行受影响 Kit/Mac 测试与 Mac/iOS 构建；用隔离实例按 verify-vibebuddy 验证真实 agent 数据。凭据、设备或已安装应用授权缺失时，完成可运行检查并明确剩余缺口，不将缺口记为通过。

完成条件：三项能力在 Mac/iPhone 的相关路径接通，关键回归和构建通过，真实摘要/音频/操作证据完整；缺少设备实听或真实调用时保持验收未完成。实现、协议验证、用户听感、提交、安装和发布分开记录。

## Out of Scope

- Firebase 项目接入、云中转、共享开发者 Key、额外账号体系或跨设备 Key 同步。
- 新的任务权限或操作种类、自动执行策略、视频/屏幕输入、声音克隆和自定义声音设计。
- 透明重连与上下文恢复、长通话无缝续接、重做全双工/AEC 音频管线、供应商自动故障切换。
- 为优化首音而重做流式播放器；除非本轮实测证明现有完整音频路径无法达到可用体验，届时明确记录规格调整。
- 更改已有通知/已读契约、扩大结果证据保留、改动 Antigravity agent 集成。
- 本规格阶段的产品实现、依赖安装、真实模型调用、安装替换、发布及跨机同步。

## 实施核对（2026-10-04）

核对 ADR-0004 正文发现其 2026-09-08 决策已取代半双工；原规格依据历史文件名误写“半双工”。已纠正为复用现有全双工/AEC 与恢复机制，不改变用户确认的通话体验或扩大音频改造范围。
