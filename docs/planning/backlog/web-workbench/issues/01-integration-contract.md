# WEB-01：跨项目 Web 工作台接入设计

Status: needs-triage

依据：[PRD](../PRD.md)，用户于 2026-10-01 提出先行铺垫。

## 目标

用真实数据确定项目、工作项、Session 和写作产物的关联方式，形成第一条 Web 流程的可实施契约。

## 工作范围

- 整合对象已确认为 Anamra（同级 `anamra`）；读取其本地指令，核实模型与可用读取入口，不假设已有 HTTP API。
- 读取一个选定论文项目的产物格式，确定只读投影；不扫描或上传全部论文原文。
- 用现有 VibeBuddy Snapshot 确定来源、会话、agent、状态与控制能力的映射。
- 给出稳定项目 ID、跨机位置、工作项到 Session 的关联样例；区分工作完成、会话结束、已读与作者验收。
- 定义已有信息到分类建议、进度变化到调度请求、执行结果到任务更新的契约；保留来源版本、人工修正、依赖、暂停与防重复派发。
- 用一条真实研究工作项验证分类 → 按 Writing Infra 进度安排 → VibeBuddy 执行 → 结果关联的样例。
- 比较本机同源 Web 服务与自用 Mac mini 聚合方案，明确浏览器认证、Mac bearer 保存、断线和多源去重。
- 明确第一条纵向流程的实际改动路径与验收步骤，再拆实施票；不预先选前端框架或新增通用插件系统。

## 完成条件

- 每个显示字段有真实来源或明确的缺失状态；样例脱敏且能追溯结构来源。
- 说明哪些接口可复用、哪些需新增，以及对现有原生客户端的影响。
- 明确身份过期、跨源不可达、重复写入的处理方式；Cloudflare 可替换而不改变项目和任务身份。
- 涉及既有 ADR 变更时列出冲突和拟议决策，不静默修改旧契约。
- 第一版用户范围、任务写入权威与 Anamra 接口核实后再评为 ready-for-agent。
