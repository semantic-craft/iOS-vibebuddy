## 用户目标

用户开启 Grok Build 后，应能看到本机已经运行的会话；如仍需操作，应在同一入口和会话卡片说明原因及下一步，不能只留下一个已勾选的开关和空列表。
用户已确认下述产品方向并要求开工单。此票落实方案与验收，不代表实现或安装版已修复；commit、push、替换安装版及发布仍按项目授权边界执行。

## 已复现的现象与原因

- 2026-10-02 对当前安装版 VibeBuddy 1.3.41（59）使用 Computer Use 走查；源码检查基线 HEAD 为 `5fe0b3bf`，工作区另有未提交改动，安装包与此 HEAD 的对应关系未核实。
- 「设置 → 用量来源 → 采集 Grok Build 账户用量」已开启，并有更新时间；该开关只控制账户额度采集，不会接入终端会话。
- 「设置 → Agent 接入」展示 Grok Build 等待活动；「设置 → 诊断」才明确展示 Hook 配置不完整，以及「修复 Grok Build hooks」按钮（AX ID `repair-grok-hooks`）。
- 本机 Grok 进程及 `~/.grok/active_sessions.json` 中的 `glaux-book` 会话存在，但 `~/.grok/hooks/` 不存在；安装版 `vibebuddy-mcp status` 两次均没有 Grok，会话列表只有 Cursor 和 Codex。
- `HookSetup.refreshScriptsOnLaunch()` / `HookInstaller.refreshOnLaunch()` 只更新已接入的脚本，不创建缺失的 Agent 配置。安装入口需用户主动点击。
- `SessionStore.retireClosedGrokSessions()` 使用注册表结束已知且进程退出的会话，不发现新会话。因此配置缺失时，打开 Grok 也不能使会话出现。
- 本次走查未点击安装/修复、未修改 Grok 配置，未验证手动接入后的结果。不能把文档中的重载路径当作已完成验收。

## 确认的产品行为

1. 在「Agent 接入」提供明确的「监控 Grok Build」开关及状态。用户开启即触发 Grok 所需的观测 hooks 配置，并开始发现本机会话；不要求跨到诊断页或运行安装命令。
2. 保留账户额度的独立控制，明确命名为 Grok Build「显示账户额度」或等义文案，说明其不控制会话监控。不能把已有额度采集偏好静默当作用户同意启用会话监控；升级后对已开启额度但未接入的用户提供可见的接入入口。
3. 开关表示用户意图，旁边的状态表示实际结果：未开启、配置中、需要重载、已接入但暂无会话、已连接（会话数）、接入失败（原因和重试）。只有真实事件证据才能表示实时连接已建立；写入成功不等于连接成功。
4. 开启后发现已经运行的 Grok，在正常一次发现周期内显示会话卡片和可用的项目名称，不必等用户发新提示。尚未收到实时信号时标明「已发现，等待接入」，不伪造 working/done、权限请求、完成通知或远程控制能力。
5. 已运行的 Grok 若需要加载新配置，在设置及卡片就地展示 `/hooks` → `r` 重载提示；若此 CLI 版本不支持热加载，给出经验证的替代步骤。接到事件后自动清除提示并更新同一张卡片，不生成重复会话。
6. 写入失败时保留可重试的错误原因；不继续显示「等待活动」掩盖失败。未安装或找不到 Grok 时明确说明，避免无限配置中。
7. 用户关闭会话监控后停止该来源的新增监控和提醒，并将已有卡片明确退出实时状态；保留历史事实。重启、升级不得自动重新开启。关闭不改变账户额度选项，也不改变 Grok 自身运行、权限模式或其他 Agent。
8. 已接入用户升级后继续工作；新偏好应兼容已有的安装记录与主动卸载意图。只管理 VibeBuddy 自己的配置项，保留其他 hooks，尊重 `GROK_HOME`。

## 实施范围与已有约束

- 入口和提示：`VibeBuddyMacApp/Sources/SettingsView.swift`、`HookSetup.swift`、会话卡片及中英文资源；控件需有稳定 AX ID，能读出对象、开关值、状态和下一步。
- 接入和发现：复用 `HookInstaller`、`GrokHome`、`GrokActiveSessions`、`GrokSessionLocator`、`SessionStore` 现有边界；先核对实际运行版本的文件结构。
- 注册表只提供发现与存活证据；保留 PID 校验、leader 下不能以终端退出推定会话结束等规则。不扫描所有历史目录冒充活跃会话，不重复接管 ACP 托管会话。
- 此方案扩展 `GLOSSARY.md` 中注册表仅用于退出清理的描述，实施时同步更新文档；不能将“发现会话”写成拥有实时控制通道。
- 保留 ADR-0030 的终端会话与 VibeBuddy 托管会话边界：本票不引入 leader attach、不新增审批 gate、不改变 Grok permission mode。沿用 ADR-0009 的本地认证，不生成或替换生产 token。
- 这是 Grok Build 的独立可实施项；与 [SET-01](../../mac-settings-usability/issues/01-settings-ux-dx-ax.md) 的设置清晰度工作关联，但不扩展为全部 Agent 的接入重构，不涉及 Grok Bot。
- 编辑前核对当前 Git 差异，尤其已有设置、中文字符串与连接功能改动；保留其他工作的未提交修改。
