# Antigravity 配额与会话观察实施规格

Status: ready-for-agent

## Problem Statement

用户在 Antigravity CLI / 桌面运行任务时，现有 VibeBuddy 不能可靠自动发现会话、显示模型组配额和真实等待，也不能保证手机读到完整结果。

## Solution

接入既有 Session、AccountUsage 和阅读链路。Mac/iPhone/Watch 使用统一 Antigravity 入口与原生身份，显示来源、独立模型池、等待原因和结果。首版只读观察，回原应用处理问题。

## User Stories

1. 作为用户，我希望原终端开启的任务自动出现，以免额外启动流程。
2. 作为用户，我希望桌面任务自动出现，以便离开 Mac 仍能观察。
3. 作为用户，我希望区分 CLI 与桌面来源，以便回正确应用处理。
4. 作为用户，我希望相同项目多个会话保持独立，以免混淆结果。
5. 作为用户，我希望同一原生会话只出现一次，以免重复提醒。
6. 作为用户，我希望每个模型组显示实际剩余额度和重置时间，以便选择模型。
7. 作为用户，我希望紧凑额度标注最紧张的模型组，以免错误理解共享池。
8. 作为用户，我希望额度不可读时标注过期或不可用，以免误以为用尽。
9. 作为用户，我希望真实问题或权限等待显示原因，以便决定何时返回。
10. 作为用户，我希望只读任务不显示无法执行的远程动作，以免误操作。
11. 作为用户，我希望恢复运行后等待卡自动消失，以免重复处理。
12. 作为用户，我希望完成、取消、失败明确区分，以免把中断当成功。
13. 作为用户，我希望断线不被当作完成，以免错过仍在运行的任务。
14. 作为用户，我希望 Mac 能读原生对话、手机能读完整最终结果，以免返回电脑找内容。
15. 作为用户，我希望长结果不静默截断，缺失时有明确说明，以便判断内容是否完整。
16. 作为用户，我希望 Watch 沿用短提醒与额度条，以便快速判断是否需处理。
17. 作为用户，我希望重启恢复不重播历史完成提醒，以免被旧任务打扰。
18. 作为用户，我希望提醒继续尊重现有关注及通知设置，以免新增噪音。

## Implementation Decisions

- 使用已验证官方 CLI `/usage` JSON，按真实模型组、窗口与 reset 归一化；不抽取 OAuth，不默认 CLI/桌面账户一致。
- CLI 读取本地原生 transcript_full 日志，短日志仅明确标记的降级来源。桌面通过同用户应用进程发现 loopback RPC，读取列表和步骤；不发送内容到第三方。
- 当前步骤的 WAITING / CANCELED 优先于列表 RUNNING；单行 DONE、文件静默或工具错误均不代表终止。CLI 问题请求须结合后续结果和原生结束信号判断。
- 更新当前 camelCase hooks 与 wrapper 事件名，保留 fail-open；不要把 headless hooks 成功当作交互式 CLI 已覆盖。
- 原生身份用于去重和阅读；CLI/桌面路径必须确定来源，标题不是身份。控制通道为 none。
- 沿用既有完成证据、消息通知、历史读取、三端展示协议。首次发现的历史记录不产生新的完成通知；恢复不得伪造 turn。
- 观测错误独立于执行失败。读取和轮询有界，取消时清理自身任务；不能探测其他用户进程或输出凭据。

## Testing Decisions

以实际 adapter→daemon snapshot→原生 UI 为主要验收边界。少量回归检查覆盖已复现的 DONE 误判、取消残留等待、短日志截断、独立池与过期处理；不为复述实现扩展测试矩阵。隔离 daemon 用临时 HOME 和非 9876 端口；使用真实 Antigravity 任务核对开始、等待、恢复、结束、失败/取消与观察恢复。三端编译与真实可用设备分别记录，模拟器结果不代替真机推送送达。发布核验必须记录实际版本、签名、渠道和产物。

## Out of Scope

远程回答/批准/启动、多账户管理、完整历史搜索与导出、新导航、云端执行、Mac App Store 改造。
