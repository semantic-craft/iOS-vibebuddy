阶段：首版实现与 Agent 功能验收完成；Mac 已发布，iOS/Watch 已提交 Apple 并等待审核。见 [集成验收记录](../../../qa/antigravity-monitor-20261004.md)。
日期：2026-10-04。
来源：本次 grill-with-docs 对话，用户对 Q1–Q4 回答“按推荐”，对 Q5 回答“就按你的推荐来”。
研究：[接入方案与开源看板比较](../../../research/antigravity-monitor-2026-10-04.md)。

## 已确认的产品决定

1. **只读观察与提醒**：首版展示运行、等待用户、完成和失败；取得等待原因时显示原因。
   等待时引导回原应用处理。远程批准、回答、启动任务属于后续阶段。
2. **三端验收**：Mac 展示详情，iPhone 查看任务与配额，Watch 沿用简短提醒和额度条。
   可以分步实现，但 Mac 单端完成不等于首版完成。
3. **统一入口**：CLI 与桌面会话归入一个 Antigravity 入口，每个会话注明来源；
   沿用项目筛选和状态分组。自动发现用户在原应用中开启的会话，不要求从 VibeBuddy 启动。
   只有确认同一原生会话身份时才合并，不能按标题或项目相同合并。
4. **按模型组显示配额**：显示实际可读的各组剩余比例、限制窗口和重置时间；
   紧凑入口显示最紧张的一项并注明组名。首版优先当前使用的账户，不加入多账户管理。
5. **任务正文**：Mac 能阅读原生会话；iPhone 至少能阅读完整的最后结果和可取得的等待原因；
   Watch 保持简短提醒。沿用现有阅读器，缺失内容明确标注；“任务已完成”不能代替实际结果。
   完整历史搜索、统计和导出不作为首版要求。

## 继承的领域约定

- 沿用 [CONTEXT](../../../../CONTEXT.md) 的 Session、needsResponse、working、done、
  waitKind、ObservationHealth、Control channel 与 AccountUsage，不创建平行词汇表。
- 一次工具错误不自动判会话失败；观测中断不自动判完成。
- 观察到等待不意味着拥有控制通道；只读等待没有远程审批或回答按钮。
- Mac / iPhone / Watch 遵守现行 agent 入口、任务阅读及通知策略，不另建 Antigravity 专属导航。
- 本阶段未形成需要独立 ADR 的新架构取舍；实现来源选择仍需原型验证。

## 范围结论

本轮产品取舍已全部回答。Mac 会话正文沿用 ADR-0024，iPhone 结果阅读沿用 ADR-0027；
不新增阅读器导航或独立领域词汇。下一阶段验证技术可行性；若原型证明无法满足某一项，
带具体证据重新讨论该项，不默默缩小已确认范围。

## 待原型回答的技术问题

- 当前 CLI transcript 和桌面 RPC / hooks 能否可靠覆盖运行、真实等待、完成及失败。
- CLI/桌面原生会话身份、重新打开、来源去重和后台任务完成的实际语义。
- 配额组、时间窗口、账户归属及三端紧凑显示映射；同组不能错误替代其他独立池。
- 已有活跃会话发现、重启恢复和旧完成记录不重复提醒。

## 首版验收标准

- CLI 与桌面分别进行真实任务验收；运行、等待、处理后继续、完成/失败与原应用一致。
- 在真实账户中对照配额比例与重置时间，三端一致；来源失联显示不可用或过期，不填零。
- 同项目多个会话独立，重复来源不产生重复卡片；从原应用开启的任务能被发现。
- Mac 可阅读原生会话正文；iPhone 可阅读完整最后结果，长文本不静默截断，结果与原会话一致。
  等待原因可取得时显示原意，缺失时标注；Watch 保留简短提醒。
- 提醒沿用现有用户通知与关注设置；三端不显示未具备控制通道的审批、回复或启动入口。
- 历史记录发现不触发旧完成提醒；观测失联不伪造完成，恢复不产生重复会话。
- 原型记录实际发现/状态更新延迟、重启恢复和正文完整性；具体性能阈值在取得实测数据后制定。
  不把仅有配额、单端显示或只有 working/done 的原型当作首版全部验收通过。
