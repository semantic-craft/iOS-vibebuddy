# vibebuddy 愿景与优先级（2026-09-05 grill 结论）

由一场 `grill-me` 会话得出（四轮、28 个决策）。它取代
`.scratch/planning/next-cycle-2026-09-05.md` 里"待你拍板"的部分；那份文档的现状调查仍然有效。

2026-09-05 补充访谈：用户确认保留主动委派，并扩展 Apple Watch；修订 Q3/Q12，新增 Q29–Q37。官方依据见 [移动端与 Watch 方案核对](mobile-watch-official-basis-2026-09.md)。本次是产品决策，不代表 #42 已验收或获准合并。

## 一句话

**vibebuddy 是 AI 编程 agent 的呼叫器与轻量委派入口：离桌后及时知道哪些会话需要你，能在手机或手腕回应、补充指令或发起任务。**
猫与图标服务于这句话；腕上语音是完成任务交互的一种输入输出方式。

## 决策树

### 根：给谁做、做什么

| # | 决策 | 结论 |
|---|---|---|
| Q1 | 用户 | 面向 App Store 公众的产品，按陌生用户标准打磨；你自己仍是第一用户 |
| Q2 | 主身份 | 呼叫器优先。猫是性格层，任何时候不能挡住"看状态、点批准" |
| Q3 | 手机能力边界 | **修订：保留 #42 的主动委派与自由文本方向、两端 New task，不按原 Q3 剥离。** 手机可回应、补充运行中任务、继续已完成会话或新建任务；Mac 保留环境配置与复杂操作。呼叫器优先，不做远程终端；具体语义、在场行为与合并条件见 Q29–Q37 |
| Q4 | 成功判据 | 连续一周没有一次因为没收到提醒而回到桌前发现会话卡着 |
| Q5 | agent 广度 | 一等：**Claude Code、Codex、Grok、Cursor**。其余（Qwen、Kimi、OpenCode、Antigravity）标"社区级、未验证、fail-open" |

| Q7 | README 承诺 | 以兑现为主；"端侧语音识别"是误述，直接改掉 |
| Q14 | 商业模式 | 免费、无内购、无追踪、无账号（ADR-0003 不变） |

### 手机与 Watch 的交互边界（补充访谈定案）

| # | 决策 | 结论 |
|---|---|---|
| Q29 | “续一句”与“新任务” | 按目标与状态区分：待答问题走原问题回答；运行中任务补充指令；已结束会话明确“继续任务”开启下一轮；“New task”创建独立会话。发送前清楚显示目标 Mac、项目与 agent，新任务只选 Mac 已有项目；不新增环境搭建或任意 shell 面板。不支持的操作给出原因，不假装四家能力一致 |
| Q30 | 在场时的操作入口 | 不因 presence 隐藏手机/Watch 主动操作入口；原生待答卡若只读，应说明在 Mac 处理，不得借自由文本绕过审批。对应会话在 Mac 前台且用户活跃时抑制重复普通提醒，判断过期或不确定时恢复基础提醒；保留用户强制手机提醒选项。重要任务例外见 Q33 |
| Q31 | 最近输出 | 做手机可展开的有界只读片段，Watch 提供短版并按需朗读；显示来源、更新时间、截断/无数据状态。只展示必要对话文本，不传 thinking、完整工具结果或终端。复用 Mac recentEntries 的思路，但逐 agent 核验格式，不能把现有本地 reader 当作手机接口已完成 |
| Q32 | Watch 直接语音 | 第一目标是“选已有任务或新任务 → 系统听写 → 确认识别文字和目标 → 发送 → 阅读/按需听取真实 agent 答复”。不把语音伴侣生成的转述充当编程 agent 答复，不自动播放敏感内容。优先官方文本输入、音频与 WatchConnectivity；不可达时明确未发送，执行结果未知时先核对，不自动重发。持续通话与常驻麦克风不属于此闭环 |
| Q33 | 最重要任务通知 | 用户显式标记“重要”；其等待回应、失败、完成进入腕上优先提醒，不被应用的 Mac 在场过滤抑制。普通任务的等待回应仍保留基础通知，在场时按 Q30 路由。重要不等于越过系统设置：尊重类别开关、Focus、佩戴/锁定与 Apple 通知路由；不承诺无条件腕上必达，不默认申请 Critical Alerts。Time Sensitive 仍限 Q23 的即时待答场景。重要标记不改变 Q25 的 follow 重复提醒规则；任一端已处理/已读就撤销相应待提醒事件 |
| Q34 | 守护进程只读命令白名单 | 本轮不增加默认放行名单。在场感知负责提醒/回应位置，权限规则负责是否批准。优先 agent 原生权限与用户明确的单次、会话或持久允许；不因命令名看似只读就默认批准。先消除重复提醒；如仍有多余审批，以实际样本另定规则 |
| Q35 | 官方依据与交付门槛 | 采用有公开官方文档的 API/CLI，核对目标版本；实验接口或未证实的端到端行为不写成成熟保证。“无弊端”落实为避免已知可规避问题、说明系统限制并真机验证，不承诺零耗电、零误识别、零延迟或必达。#42 保留能力方向，但应修正 steer 失败静默改 start、在场推送过滤及状态语义，验证重复发送/断线结果与真实两端流程后再评估合并。新增 Watch/输出能力是后续实现范围，不以决策文档宣称 #42 已具备 |
| Q36 | Watch 默认任务目标 | 默认先选定任务再口述。从任务通知进入绑定该任务，并按当前待答状态回应；从详情进入绑定该任务，按 Q29 区分补充与继续。从表盘或首页进入显示“继续最近任务”和“新任务”，不直接向最近任务发送。新任务可选择手机预设的 Mac／已有项目／agent 常用组合；发送前始终显示并确认目标和识别文字。语音识别目标只作后续快捷方式，不猜测后直接执行 |
| Q37 | Watch 回复呈现 | 按状态呈现：需要回应时展示完整问题或审批对象及影响判断的必要内容，放不下则提示到手机查看，不以截断内容诱导决定；执行中显示最新简短进展，默认不震动、不自动朗读；完成后先显示结果短片段，可展开或按需朗读，全文在手机查看；失败时展示实际原因和可用操作，原因未知则如实说明。首版使用 agent 原始文字，截断明确标注，不新增模型改写摘要。最近输出范围与来源按 Q31，通知策略按 Q33 |

这些是自有产品策略；官方提供底层机制，并没有为本产品的在场阈值、重要任务分级或跨端必达背书。Apple 的通知镜像不能保证 iPhone 使用中仍在腕上提醒；独立 Watch APNs 有官方路径，但需要单独设计与设备验收，不因“独立交互端”自动扩大为脱离手机直连 Mac。

## 1.2 范围（按依赖排序）

每一步以可运行、可在真机验收的产物收尾。A = agent 可交付，U = 只能由你完成。

1. **清账**（U）关闭 PR #24；合并 #28、#26。（A）分类通知分支合到最新 main 并开 PR。
2. **可靠性**（A）七类开关、可操作横幅、Time Sensitive、`filtered` 日志、follow、漏接计数、`.p8` 内置与新 ADR、Qwen 重拨。（U）APNs 真机 `accepted` 记录、Focus 下锁屏按钮验收。
3. **陌生用户路径**（A）Swift 安装器（四家）、Cursor 适配器、Mac 首次运行流程、Demo 数据含四家。（U）四家真机验收矩阵（Q27）。
4. **交互与外观**（U）装 Xcode 27。（A）白色小猫的 Icon Composer 分层图标、iPhone Dashboard 与 Settings 重排、手表 Q32/Q33 的通知、口述任务与答复闭环、Q31 最近输出。（A）README 与 App Store 文案按上节改。
   移动交互按 Q29–Q37 分步验收：Mac 在场/离场、手机锁定/解锁、Watch 佩戴/锁定、Focus、网络中断、语音误识别、重复点击、跨端确认撤销；未通过的能力不得宣传为已支持。Watch 耗电与朗读体验需在真实设备验证。
5. **验收与发布**（U）自装三端，跑满一周；漏接计数为 0 后 `tools/release-mac.sh` 发 Mac 1.2（首次真实 Sparkle 更新），iPhone / Watch 1.2 提交 App Store。

第 2 步与第 3 步可以并行；第 4 步等第 3 步的首次运行流程定型后再动 UI。

## 明确不做

- 远程终端、手机端环境搭建与任意 shell 控制；手机发新任务已纳入 Q3/Q29
- 中继服务器、任何 vibebuddy 云（Q8、Q16）
- 自建端侧语音识别层（Q11）、持续腕上实时通话及语音续接状态机（Q17/Q32）；系统听写与按需朗读允许
- 重开图标或宠物的身份讨论（Q20，已由 #30/#35/#38 定案）
- 手表脱离 iPhone 直连 Mac 执行任务（Q12/Q32，本周期不做）
- follow 间隔可配（Q25）
- 为 Qwen / Kimi / OpenCode / Antigravity 做真机验证（Q5）
