# vibebuddy 愿景与优先级（2026-09-05 grill 结论）

由一场 `grill-me` 会话得出（四轮、28 个决策）。它取代
`.scratch/planning/next-cycle-2026-09-05.md` 里"待你拍板"的部分；那份文档的现状调查仍然有效。

## 一句话

**vibebuddy 是 AI 编程 agent 的呼叫器：你离开桌子后，不错过任何一个在等你的会话，并且能在手机或手腕上一键回应。**
猫、语音、图标都是这句话的皮，不是骨。

## 决策树

### 根：给谁做、做什么

| # | 决策 | 结论 |
|---|---|---|
| Q1 | 用户 | 面向 App Store 公众的产品，按陌生用户标准打磨；你自己仍是第一用户 |
| Q2 | 主身份 | 呼叫器优先。猫是性格层，任何时候不能挡住"看状态、点批准" |
| Q3 | 手机能力边界 | 停在"不错过 + 一键回应"。最多加"给等待中的会话续一句"，不做远程终端 |
| Q4 | 成功判据 | 连续一周没有一次因为没收到提醒而回到桌前发现会话卡着 |
| Q5 | agent 广度 | 一等：**Claude Code、Codex、Grok、Cursor**。其余（Qwen、Kimi、OpenCode、Antigravity）标"社区级、未验证、fail-open" |
| Q6 | Mac 定位 | Mac 仍是一等界面（glance 是桌前主视图）；手表要深化和扩展 |
| Q7 | README 承诺 | 以兑现为主；"端侧语音识别"是误述，直接改掉 |
| Q14 | 商业模式 | 免费、无内购、无追踪、无账号（ADR-0003 不变） |

### 可靠性（服务 Q4）

| # | 决策 | 结论 |
|---|---|---|
| Q8 | 关闭 App 后送达 | APNs `.p8` 内置进 Mac App，不做中继服务器。隐私文档一句话说明影响面 |
| Q13 | 漏接度量 | 做进 App：任一 needsResponse 超过 5 分钟未在任何一端确认即计一次漏接，Mac 设置页显示本周计数 |
| Q18 | 横幅直接操作 | approval 横幅 Approve（需解锁）/ Deny；question 横幅文本输入作答；Mac 横幅同样加按钮；手表镜像自动继承 |
| Q23 | Time Sensitive | approval 与 question 两类用 `timeSensitive`，其余普通级别 |
| Q24 | 第七类 | `quota`（配额 / 预算）独立成类，Mac 默认开，手机默认关 |
| Q25 | follow 提醒 | 固定 5 分钟 × 12 次、任一端确认即停，不可配 |
| Q26 | 被过滤的提醒 | 在 `NotificationDeliveryLog` 记 `filtered` |
| Q16 | 离开局域网 | 不做远程批准。通知如实写"回到同一网络后处理"；Tailscale 作 README 进阶说明 |

### 陌生用户路径（服务 Q1）

| # | 决策 | 结论 |
|---|---|---|
| Q9 | 量化标准 | 从下载 DMG 到第一条手机通知 10 分钟内，全程不开终端 |
| Q15 | hook 安装器 | 四家一等 agent 的安装逻辑用 Swift 在 Mac App 内实现；Python 脚本留给社区级，不进界面 |
| Q10 | "一等"的定义 | 三态追踪 + 远程审批必须；配额与跳转尽力 |
| Q19 | Cursor hook | 用户级 `~/.cursor/hooks.json`；审批由我们的 hook 自己阻塞等手机（Cursor 的 `ask` 不被强制） |
| Q27 | 验收 | 每家一份真机清单：三态各一次、手机批准一次、手表批准一次、App 被杀后 APNs 送达一次；截图存 `.scratch/qa-shots/<agent>/`；Demo 数据含四家 |

### 皮：语音、猫、UI

| # | 决策 | 结论 |
|---|---|---|
| Q11 | 语音层级 | 维持 BYO-key 实时对话，不加端侧层。"会用的人自己会用" |
| Q17 | 供应商上限 | 到顶提示"通话结束"，一键重拨，不带上下文 |
| Q20 | 猫的身份 | 像素猫贯穿全部；App 图标用 Icon Composer 把同一只像素猫做成分层版（Default / Dark / Clear / Tinted）；软 3D 草稿丢弃；ADR-0006/0007 不动 |
| Q12 | 手表顺序 | (b) 腕上审批加固与口述作答 → (a) 复杂功能与 Smart Stack 三色计数 → (e) 按类别震动 → (c) 腕上语音 → (d) 脱离 iPhone 直连 |
| Q21 | UI 面顺序 | Mac 首次运行流程 → iPhone Dashboard → 两端 Settings 信息架构 → 手表 → Live Activity → Mac 三栏 Dashboard |
| Q22 | 目标 SDK | Xcode 27 SDK 构建；部署目标维持 iOS 17 / macOS 14；Liquid Glass 只接受系统免费给的部分 |
| Q28 | 发布节奏 | **一版发完**：1.2 同时包含可靠性与陌生用户路径，先在你自己的设备上跑满一周零漏接，再提交 App Store |

## 需要兑现的 README 承诺

- 从锁屏批准（Q18）
- 关闭 App 后仍能收到（Q8）
- "Works across your whole agent fleet"改为"四家一等 + 社区级"的诚实分级（Q5）
- 删除"recognizes speech on-device"（Q7）
- 平台门槛改回实际的 iOS 17 / macOS 14（Q22）

## 对现有决定的改动

- **新 ADR**：APNs 密钥内置于 Mac App 的理由与影响面（Q8）。
- **新 ADR 或修订 ADR-0009**：Cursor 审批由 vibebuddy hook 阻塞实现（Q19）。
- **ADR-0001** 修订定稿（PR #28 已起草），加入"到顶即重拨"（Q17）。
- **ADR-0003、0006、0007** 保持；0006/0007 追加一句"App 图标为同一像素猫的 Icon Composer 分层版"。
- **`.scratch/notification-categories/PRD.md`**：决定 5（不用 Time Sensitive）被 Q23 推翻；决定 1（手表零代码只镜像）在通知层面维持。
- **CONTEXT.md 新词条**：NotificationCategory（七类）、Followed、CompletionReminder、Missed、Quota category、First-class / Community-tier agent。

## 1.2 范围（按依赖排序）

每一步以可运行、可在真机验收的产物收尾。A = agent 可交付，U = 只能由你完成。

1. **清账**（U）关闭 PR #24；合并 #28、#26。（A）分类通知分支合到最新 main 并开 PR。
2. **可靠性**（A）七类开关、可操作横幅、Time Sensitive、`filtered` 日志、follow、漏接计数、`.p8` 内置与新 ADR、Qwen 重拨。（U）APNs 真机 `accepted` 记录、Focus 下锁屏按钮验收。
3. **陌生用户路径**（A）Swift 安装器（四家）、Cursor 适配器、Mac 首次运行流程、Demo 数据含四家。（U）四家真机验收矩阵（Q27）。
4. **皮**（U）装 Xcode 27。（A）像素猫分层图标、iPhone Dashboard 与 Settings 重排、手表 (b)(a)(e)。（A）README 与 App Store 文案按上节改。
5. **验收与发布**（U）自装三端，跑满一周；漏接计数为 0 后 `tools/release-mac.sh` 发 Mac 1.2（首次真实 Sparkle 更新），iPhone / Watch 1.2 提交 App Store。

第 2 步与第 3 步可以并行；第 4 步等第 3 步的首次运行流程定型后再动 UI。

## 明确不做

- 远程终端、从手机发新 prompt（Q3）
- 中继服务器、任何 vibebuddy 云（Q8、Q16）
- 端侧语音层（Q11）、语音续接状态机（Q17）
- 软 3D 猫（Q20）
- 手表脱离 iPhone 直连（Q12 最后一项，本周期不做）
- follow 间隔可配（Q25）
- 为 Qwen / Kimi / OpenCode / Antigravity 做真机验证（Q5）
