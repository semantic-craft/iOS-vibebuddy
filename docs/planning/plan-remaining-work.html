## 这份实现在做什么

对应 ticket .scratch/codex-desktop-monitoring/issues/04-jump-to-desktop-thread.md（ready-for-agent）。

问题：Codex Desktop 的会话是从 ~/.codex/sessions 的 rollout 文件观察到的，Desktop 不执行 CLI
hook，所以这类会话永远没有 terminalRef，跳转按钮因此被隐藏。但它有 thread id（就是 rollout 的
session id），而 ChatGPT.app 声明了 codex URL scheme，codex://threads/<id> 能既前置 App 又切到
那条对话。

已写好的实现：
- VibeBuddyKit Models.swift：AgentSession 加可选字段 desktopThreadID，加两个派生属性
  canJump（terminalRef != nil || desktopThreadID != nil）和
  jumpsToDesktopThread（terminalRef == nil && desktopThreadID != nil）。
- HookEvent 加可选 desktopThreadID；只有 rollout tailer 会设它。
- CodexRolloutParser.event(...) 带上 desktopThreadID: sessionID 和 observationSource: .rollout。
- SessionReducer 把它落到会话上（非 sessionEnd 事件时）。
- SessionStore 加 desktopThreadID(for:) 读取。
- VibeBuddyServer 加 onJumpToDesktopThread 闭包；/jump 路由在没有 terminalRef 时走它。
- 新文件 CodexDesktopJumper：把 codex://threads/<id> 直接投给 ChatGPT.app 的 bundle
  （com.openai.codex，已核实：/Applications/ChatGPT.app 的 CFBundleIdentifier 就是这个，
  并且它声明了 codex scheme）。之所以不用通用 open，是因为本机 LaunchServices 上有四个过期的
  codex: 声明，按策略解析可能落到一个已经不存在的副本上。
- Mac 与 iOS 两端的跳转控件改为按 canJump 显示、按 jumpsToDesktopThread 改文案与图标：
  DashboardView（两端）、GlanceView、JumpOutcomeCopy、MenuBarModel、DashboardStore、JumpRoutesTests。
