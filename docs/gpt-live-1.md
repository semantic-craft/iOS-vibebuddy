# GPT-Live 1 接入与工作流评估

核对日期：2026-09-11。这里区分官方能力、源码实现与实际验收；当前已安装 Mac/iPhone 验收版，未发布。

## 能力与适用位置

GPT-Live 1 是语音会话模型，支持同时听和说、自然打断，并把推理和工具使用委派给后端。它接受音频和文本，输出音频和文本，使用独立 Live 接口；不能把模型 ID 直接放进原来的 Realtime 或完成摘要请求。[模型文档](https://developers.openai.com/api/docs/models/gpt-live-1)、[迁移指南](https://developers.openai.com/api/docs/guides/live-migration)。

这次采用 Responses delegation：Live 负责交谈，独立文本模型负责判断和选择工具，VibeBuddy 继续执行本地校验及操作。默认后端为 GPT-5.6 Luna，Mac 与 iPhone 都可单独修改后端模型；仍使用已有 OpenAI Keychain 凭据。Luna 支持 Responses、函数调用及 `none` 推理强度，适合先测试状态查询和短摘要。[委派文档](https://developers.openai.com/api/docs/guides/live-delegation)、[Luna 文档](https://developers.openai.com/api/docs/models/gpt-5.6-luna)。这不是对 Luna 与 Terra 质量差异的实测排名。

语音按会话时长、以秒计费，后端模型与工具另外计费；当前所读模型页未提供可引用的具体费率，因此不在代码或本文猜测金额。[连接与计费说明](https://developers.openai.com/api/docs/guides/live)。

## 已实现的行为

- 新的 OpenAI 默认语音模型为 `gpt-live-1`。已明确保存的其他模型选择继续按对应接口运行，Live 失败不会自动换接口重试。通话与 Settings 连接检查共用选路。
- 前端提示词只负责语言、节奏、打断与委派条件；任务规则、证据边界和操作要求放在后端。官方也建议这样拆分，避免把长流程塞进语音提示词。[提示词指南](https://developers.openai.com/api/docs/guides/live-prompting)。
- 通话中通过只读工具重新查询用户选中的任务，包含当前状态、当前问题和已结束任务的摘要。运行中任务的上一轮摘要不作为当前进度或待确认事项；操作目标也必须在选中范围内。
- 连续字幕分别累积两位说话者的片段，不把片段当作编程任务的确认或工具授权。完整、明确的通话结束命令在文字稳定 750 毫秒后可由本地直接挂断；否定、引用和询问不匹配。Live 的打断不取消正在执行的后台任务。
- 保留完整音频流，另计实际有声片段的播放状态，避免静音包让“正在说话”一直亮着。Live 不制造 Realtime 的 `response.done` 或 truncate 事件。[会话管理](https://developers.openai.com/api/docs/guides/live-conversations)。
- 语音挂断先停止本地音频，按序回传挂断工具结果并等待必要后端响应（上限五秒），再发送 `session.close`；发送完成后最多等待十秒接收最终事件。没有收到最终事件仍保留“最终用量未确认”的状态。
- 完成摘要继续使用独立、无工具、`store: false` 的文本请求；拒绝将 Live/Realtime 模型用于摘要。未更改摘要开关、提供商选择、12 秒通知期限或失败后的普通通知行为。

## 摘要怎样更有用

“更激进”落实为更强的筛选和更清晰的结论，而不是提高成功表述的强度。通知先讲最影响判断的结果或阻塞，再讲有依据的影响和下一步；合并重复检查、删除命令流水账，保留每一个会改变用户判断的独立限制。仍限制为一至两句、最多 180 字符。

例如，同样是“构建通过、部署认证失败”，应先说“部署被认证失败阻断”，而不是先庆祝构建成功。仅交付方案时应说“方案已准备”，不能变成“问题已修复”。如果没有待用户处理的事项，就说明无需介入，不因还有运行中的任务而制造催办。

更适合后续评估的方向是：用户先听简报，再追问某一任务；交谈期间刷新状态；将复杂判断交给更强的后端。跨任务自动排序、主动插播通知、自动审批或自动启动任务没有在这次接入中实现。它们需要独立定义触发条件、上下文范围与验收标准，不能仅靠一条更强的系统提示词宣称完成。

- Mac Debug 与 iOS Simulator 的完整应用构建通过。另启动独立 bundle ID、独立状态目录和端口的 Mac 构建，实际检查 Settings 中的 Live 模型、任务推理模型及 Luna 摘要设置；没有替换运行版，也未修改其功能开关。
- Kit 的 47 项相关测试通过，其中包含真实 Live API：将合成中文语音按实时节奏输入，查询本项目真实 Codex 任务快照，完成只读工具调用、后端回答、语音回复及正常关闭。最终用量事件确认为 32 秒；这不等于具体金额核算。
- 该实测暴露了“运行中任务携带上一轮待确认摘要”的误导，现已从当前进度上下文中排除。修改后的实际播报包括：“它还在运行中，但没有任何需要你回答或批准的事项。先让它继续跑就行。”对没有结果摘要的已结束任务，明确表示尚无法判断后续处理。
- Mac Core 的 10 项摘要测试通过。另以现有凭据调用真实 Luna API，人工核对五份输出：部分完成、部署受阻、仅交付方案、夹带指令的原文，以及本任务上一轮真实结束文本。五份均有效返回，单份约 1.47–3.45 秒，保留重要边界并忽略夹带指令。部署样本输出：“部署因服务账户认证失败而中止，线上仍是旧版本；需由用户在服务控制台恢复认证后才能继续部署。”这是小样本验证，不是广泛质量保证。
- 按仓库规范与本次需求进行了本地差异复核，检查凭据使用、工具执行边界、双端配置和字幕/播放行为；`git diff --check` 通过。没有提交、推送、发布或跨机操作。
